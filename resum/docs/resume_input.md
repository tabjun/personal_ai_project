# 공통 이력서 입력 규격 v1

이 프로젝트 내부 데이터는 **`job-agent.resume/v1`**이다. 사용자는 JSON을 작성할 필요 없이 **Word(.docx)** 빈 양식 또는 화면에서 직접 작성한다. Markdown·JSON도 선택할 수 있다. 외부 기관의 공식 표준은 아니다. 모든 형식은 같은 공통 이력서로 가져오며 사실 검수 후 이력서 정리와 회사 양식 변환에 사용한다.

## 구조

```json
{
  "format": "job-agent.resume/v1",
  "fields": [
    {
      "id": "experience_description",
      "label": "경력",
      "value": "",
      "reviewed": false,
      "evidence": []
    }
  ]
}
```

- `id`: 변하지 않는 고유 영문 경로. `label`은 화면 제목이며 매핑 키가 아니다.
- `value`: 원문/검수된 문장. 모르는 값은 빈 문자열로 둔다. 날짜·회사·성과 수치 등을 자동 추정하지 않는다.
- `reviewed`: 사용자가 사실과 출처를 검수했는지 표시한다. 형식 검증이나 LLM의 판단으로 사실성을 보증하지 않는다.
- `evidence`: `{"source_id":"source_1","paragraph_index":0,"text":"근거 원문"}` 배열. 원문 문단 번호와 실제 근거를 보존한다. 직접 입력 후 확인한 사실은 `source_id: "user-confirmed"`로 구분하며 문서 근거와 혼동하지 않는다.

필수 최상위 키는 `format`, `fields` 두 개이다. 각 필드는 위의 다섯 키와 선택적 `items`를 갖는다. 반복 항목은 `job_agent/documents/sections.py`의 스키마에 따른 객체 배열로 보관하며 `value`는 해당 배열에서 정해진 항목명 순서로 생성한다. 값/정형 자료 불일치, 잘못된 날짜, 재직 중 종료일, 중복 ID, 근거 구조를 검사한다. 최대 200개 섹션, 섹션별 값 30,000자, 반복 레코드 최대 50개, 세부 값 최대 5,000자다. 미검수 값·근거 없는 승인·이름 없는 비어 있지 않은 레코드는 실행을 차단한다. 작성 중의 불완전한 레코드는 임시 반영할 수 있다.

## 기본 항목

| ID | 내용 |
| --- | --- |
| `headline`, `summary` | 제목, 소개 |
| `experience_description`, `department` | 경력 기술, 직무·부서 |
| `education_description`, `project_description` | 학력, 프로젝트 |
| `award_certification_description`, `cover_letter` | 자격·수상, 자기소개서 |
| `skills`, `links` | 실제 사용 기술, 공개 가능한 링크 |
| `name`, `email`, `phone` | 제공된 인적사항, 선택 입력 |
| `employment_type` | 확인된 재직 형태 |

## 반복 입력 항목

| 섹션 | 주요 세부 항목 |
| --- | --- |
| 경력 | 회사명, 부서, 직무명, 직급, 고용 형태, 시작·종료 월, 재직 중, 업무, 성과 |
| 학력 | 학교, 전공, 학위, 재학 기간, 학적 상태, 학점·만점, 비고 |
| 기술 | 기술명, 분류, 숙련도, 사용 경험 (기술 하나당 추가) |
| 프로젝트 | 이름, 기관, 기간, 역할, 팀 규모, 사용 기술, 수행 내용, 성과, 링크 |
| 자격증 | 이름, 자격번호, 발급기관, 취득일, 만료일, 비고 |
| 수상 | 이름, 수여기관, 수상일, 등급·훈격, 내용 |
| 어학 | 언어, 시험, 점수·등급, 성적번호, 응시일, 만료일 |
| 교육·활동 | 이름, 기관, 기간, 시간 또는 역할, 내용 |
| 논문·특허 | 제목, 학술지 또는 번호·상태, 날짜, 역할, 요약 |
| 링크 | 이름, 주소 |

원문 경력은 그대로 유지한다. 항목별로 옮기기를 선택할 때만 첫 레코드의 설명에 보존하며 회사명·날짜를 추측하지 않는다. 자격·수상 통합 필드는 이전 자료에 값이 있을 때만 표시한다. 내부 레코드 추가는 포털에서 경력 행을 자동 생성했다는 의미가 아니다. 기존 포털 변환에는 정형 항목의 표시 텍스트를 연결하며 실제 반복 필드/custom 위젯 저장은 별도 구현·검증이 필요하다.

## 사용 순서

1. **공통 이력서 → 빈 양식**에서 기본 Word 또는 Markdown·JSON을 선택한다. Word는 표의 항목명과 제목을 유지하고 값 칸만 작성한다. 여러 항목은 제목과 표를 함께 복사한다. 화면의 항목별 추가 버튼으로 직접 작성해도 된다.
2. **표준 이력서 업로드**로 DOCX·Markdown·JSON을 가져온다. Word의 정형 표와 Markdown의 항목명으로 결정론적으로 읽는다. 일반 DOCX는 소개 칸에 원문을 보존하고 직접 나누어 입력한다. JSON의 이전 master도 지원한다. 임의 문서의 자동 의미 분류나 OCR은 제공하지 않는다.
3. 값을 수정하고 저장한다. 변경된 값/근거는 서버에서도 검수 승인을 해제한다.
4. 출처 근거와 문장을 확인하고 **원문·사실 검수 완료**를 선택한 뒤 다시 저장한다.
5. **이력서 정리**를 실행해 내용과 순서를 확인한다. **정리 결과로 회사 양식 변환**에서 명시 검수하면 정리본을 변환 입력으로 선택한다. 공통 원본은 덮어쓰지 않는다. 정리 이력서 다운로드도 같은 세 형식을 지원한다. 회사 target/DOM/bindings는 목적지 설정이며 고급 변환 입력은 현재 JSON이다.

`result/resume_profile/profile.json`이 로컬 저장본이다. 다운로드도 같은 규격이다. JSON 재가져오기는 검수 승인을 초기화한다. 기존 CLI/HTTP의 원문·master 입력은 호환성을 위해 유지하지만 UI에서는 공통 입력을 사용한다. AI 생성 결과를 저장본에 자동 덮어쓰지 않는다. 개인 JSON, 원문, 출처 목록은 Git에 올리지 않는다.

## 다운로드·업로드·사이트 저장

빈 양식과 작성본은 DOCX·Markdown·JSON을 지원한다. DOCX·Markdown은 읽기 쉬운 내용/정형 필드를 보존하고 가져올 때 새 문서 근거를 부여한다. JSON은 원래 출처 근거도 보존한다. 어느 형식도 가져온 검수 승인을 재사용하지 않는다. 파일은 2MB 이하, DOCX XML 본문도 2MB 이하로 제한한다. DOCX ZIP/XML은 로컬 정적 라이브러리 fflate와 DOMParser로 브라우저에서 처리하며 외부 CDN·서버 문서 업로드·LLM을 사용하지 않는다. 공개 체험의 서버 `/api/extract`는 계속 차단한다.

회사 양식 변환 화면의 **사이트 업데이트·저장**은 캐치·잡코리아·사람인·원티드·인크루트를 선택해 사용한다. 전용 브라우저에서 로그인/기존 편집 화면을 열고, 현재 화면 확인 → 원문 항목/목적지와 저장 동작 검수 → 동의 → 입력·저장 순서다. 확인된 연결은 다음 수집 때 재사용한다. 선택하지 않은 값, 공개 설정, 약관 동의, 지원서 제출은 조작하지 않는다. 저장하기 버튼 또는 원티드 자동저장을 선택하고 재접속으로 값이 유지될 때만 완료 처리한다.

각 포털의 로그인/목록/지원 페이지는 제외한다. 전용 프로필은 일반 Chrome 로그인과 별개이다. 매핑과 저장 버튼은 실제 DOM에서 수집한 것만 사용하며 임의 selector를 API로 실행하지 않는다. 원문/편집 페이지/필드/저장 버튼 변경 시 실행을 차단한다. 기존 값 백업·확인된 연결·실행 기록은 `result/site_sync/`에 개인 자료로 저장한다. 저장 실패는 일부 입력이나 저장이 발생했을 가능성을 표시하고 자동 재시도/자동 원복하지 않는다. 중복 실행 토큰도 차단한다.

현재 저장 전용 버튼은 `저장`, `저장하기`, `이력서저장`, `이력서 저장`, `이 부분만 저장`, `모두 저장`만 허용한다. `작성완료`, `지원하기`, 공개 설정 등 의미가 더 넓은 버튼은 누르지 않는다. 확인 팝업도 자동 수락하지 않는다. 저장 후 목록 이동/접힌 섹션 때문에 같은 필드를 다시 확인할 수 없으면 저장 미확인으로 남기며 화면에서 직접 확인한다. 반복 항목 생성/custom 위젯/회사 자체 URL 저장은 후속 구현이다. 실제 포털별 저장 종단 검증과 로컬 테스트 사이트 검증은 다르다.

## 기존 자료 적용 범위

기존 선택·검수한 DOCX 6개의 로컬 마스터와 근거 연결은 보존한다. 이번 정형 폼 설계는 knowledge의 경력 이력서와 취업 폴더의 공통 경력·경험·데이터 분석가·CV 문서, 이력서·지원서 PDF의 추출 가능한 항목을 참고했다. 경력 내용 자체를 공개 빈 양식/예시에 넣거나 자동 승인하지 않는다. 텍스트가 없는 PDF·HWP·이미지 증빙까지 전부 읽었다고 주장하지 않으며, 이 자료의 OCR/자율 사실 분류는 별도 작업이다. 주민번호·보훈·장애 정보는 공통 기본 입력에 추가하지 않는다.

공통 형식이 안정되면 LLM 없이 원문 정렬, 값 연결, 필수항목 검사와 제한 검증을 반복할 수 있다. 새 회사 문항의 의미 판단, 경험 요약/문장 개선은 별도 규칙·사용자 작성 또는 선택형 AI 영역이며 입력 형식만으로 해결되지는 않는다.
