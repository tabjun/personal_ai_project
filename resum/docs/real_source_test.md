# 실제 DOCX 입력 테스트 (2026-10-06)

## 범위와 결과

원본: `knowledge/윤태준 경력 이력서.docx`. 원문 92개 비어 있지 않은 문단을 OOXML 문서 순서로 추출했다. 경력 담당업무 572자와 소개문 392자를 생성 없이 사용했다. 연락처/주소는 입력하지 않았다.

| 인크루트 | 이력서 접근 | 로그인 후 2단계 인증에 막혀 입력 미실행 |

실제 화면 테스트는 로그인된 Chrome의 브라우저 도구 Playwright locator로 수행했다. Python CLI가 동일한 Chrome 세션에 붙어 수행한 테스트는 아니다. Python 입력기의 실제 원본 데이터 경로는 별도의 로컬 Chromium fixture에서 검증했다.

## 발견한 동작

- 원티드는 포커스 이동 시 `자동 저장 중` 표시가 나타난다. `작성 완료`를 누르지 않아도 서버에 전송될 수 있다. 소개문 복원 후 새로고침하여 원래 값이 유지되는 것을 확인했다.
- 원티드 회사명은 기존에 `신입`이므로 원문의 재직 경력을 그 항목에 잘못 연결하지 않았다. 경력 생성/재직기간/재직형태 선택은 아직 테스트하지 않았다.
- 단순 입력 직후 읽기만으로는 제어형 UI의 반영을 충분히 확인할 수 없다. 입력기에 Tab 포커스 이동 후 readback 검증을 추가했다.
- 저장/작성완료/지원 버튼은 누르지 않았다. 캐치/잡코리아/사람인의 서버 저장이나 새로고침 후 신규 내용 유지 여부는 검증하지 않았다.
- DOM 유효성 통과는 사이트 전체 필수항목 충족 또는 저장 성공을 뜻하지 않는다.

## 재현

```powershell
.\.venv\Scripts\python.exe resume_source.py --source 'knowledge/윤태준 경력 이력서.docx'
$env:RESUME_TEST_DOCX = 'knowledge/윤태준 경력 이력서.docx'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

10개 테스트 통과. 실제 DOCX 통합 테스트는 원본 경력/소개를 5개 사이트 패키지로 만들고, 검수된 액션 생성 → Python 입력기 preflight → 로컬 textarea 입력 → blur 반영 → 원문과 값 일치를 확인한다. 환경변수가 없으면 개인 DOCX 테스트는 skip한다. 외부 사이트 저장을 검증하는 테스트가 아니다.

원문 Markdown, 문단 근거, 5개 사이트 JSON은 `result/source_resume_test/`에 생성하며 Git에서 제외한다. 여기에 포함된 개인 원문은 커밋하지 않는다.

## 남은 작업

- 인크루트 사용자 2단계 인증 후 실제 편집 화면 조사 및 입력 검증.
- 각 사이트의 반복 경력/학력 생성, custom combobox/날짜/태그 선택 adapter.
- Python 전용 로그인 프로필에서 실제 매핑 수집 → 검수 → 입력 CLI의 사이트별 실행 검증.
- 사용자 수동 저장 후 서버 영속성 확인. 전체 이력서 동기화 에이전트가 완성된 상태는 아니다.
