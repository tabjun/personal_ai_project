# 에이전트 기술 가이드

이 문서는 이 프로젝트에서 에이전트가 참고할 기술 철학, 설계 기준, 권장 워크플로우를 정리한다. 강제 규칙은 `AGENTS.md`가 우선한다.

## 1. 핵심 기술 축

### 채용 정보 수집과 정규화

- 여러 채용 플랫폼의 공고를 동일한 비교 기준으로 정리한다.
- 직무명, 요구 기술, 경력 수준, 우대사항, 마감일, 기업명, 근무 형태를 구조화한다.
- 검색 결과는 누락과 중복이 생기기 쉬우므로 원문 링크와 추출 근거를 함께 유지한다.

### 기업 분석과 지원 우선순위

- 공고 매칭만 보지 않고 기업 안정성, 성장성, 평판, 직무 적합성, 사용자의 커리어 방향을 함께 본다.
- DART, 기업 소개, 채용 페이지, 평판성 정보는 성격이 다르므로 출처별 신뢰도를 구분한다.
- 단정적 표현보다 판단 근거와 불확실성을 함께 남긴다.

### 이력서/자기소개서 맞춤화

- JD의 언어를 사용하되 사용자의 실제 경험 범위를 넘지 않는다.
- 기술 키워드를 단순 삽입하지 말고 경험, 문제, 행동, 결과의 구조로 재작성한다.
- 근거가 있는 성과 수치는 유지하고, 없는 수치는 만들지 않는다.

### 채용 사이트 양식 변환

- 사이트마다 이력서 섹션, 글자수, 태그, 필수 입력 필드가 다르므로 공통 이력서를 그대로 복사하지 않는다.
- 원티드/점핏/LinkedIn은 공개 프로필과 기술·프로젝트 요약을 중시하고, 사람인/잡코리아/캐치는 정형 필드와 자기소개 문항을 중시한다.
- 실제 사이트 저장은 로그인 세션, DOM 구조, 사용자 최종 확인이 필요하므로 먼저 JSON/Markdown 입력 패키지를 생성한다.
- 자동 저장 단계에서는 민감 필드와 제출 버튼을 반드시 사용자 확인 뒤 처리한다.

### Agentic Workflow

- LangGraph/LangChain 흐름에서는 상태, 도구, 프롬프트, 결과 저장 경계를 명확히 한다.
- 도구 호출은 관찰 가능한 입력과 출력을 남기고, 모델 판단과 실행 결과를 섞지 않는다.
- 에이전트가 긴 작업을 수행할 때는 중간 결과를 파일이나 상태로 보존해 재개 가능하게 한다.

## 2. 문서 처리 원칙

- `knowledge/`는 사실 데이터베이스로 취급한다.
- `more_info/`는 사용자의 스타일, 가치관, 작성 방향을 담는 보조 지침으로 취급한다.
- HWP, PDF, DOCX 등 원문 문서는 가능한 한 구조를 보존해 읽는다.
- 원문에서 확인되지 않은 정보는 "추정" 또는 "확인 필요"로 분리한다.

## 3. 보고서 기준

- 결과만 나열하지 말고, 왜 그 기준으로 판단했는지 설명한다.
- 채용 공고 분석은 매칭 이유, 리스크, 보완할 이력서 포인트를 함께 제시한다.
- 자기소개서/이력서 수정 결과는 어떤 JD 요구사항을 반영했는지 추적 가능해야 한다.
- 최종 산출물과 내부 분석 메모를 구분한다.

## 4. 권장 워크플로우

1. `AGENTS.md`, `skills.md`, `process.md`, `history.md`, `conversation_l2_cache.md`를 읽는다.
2. 기존 코드와 문서를 먼저 검색한다.
3. 에이전트 구조 변경이면 상태 모델, 도구 목록, 프롬프트 경계를 먼저 파악한다.
4. 이력서/자소서 생성 로직이면 `knowledge/`와 `more_info/`의 사실성 가드레일을 먼저 확인한다.
5. 사이트별 이력서 변환이면 대상 사이트 프로필, 필수 필드, 민감 필드, 저장 전 검수 항목을 확인한다.
6. 검색/수집 로직이면 원문 링크, 중복 제거, 결과 저장 형식을 확인한다.
7. 경량 검증을 수행한다.
8. 결과를 `history.md`, `process.md`, 필요 시 `conversation_l2_cache.md`에 기록한다.

## 5. 로컬 스킬 사용 기준

`.agents/`나 `.codex/`에 설치된 스킬은 로컬 실행 보조 도구이며 Git에 넣지 않는다.

- 버그나 실패 재현에는 diagnosing-bugs 계열 스킬을 쓴다.
- 기능을 테스트 우선으로 만들 때는 TDD 계열 스킬을 쓴다.
- 에이전트 경계, 상태, 도구 설계는 codebase-design 또는 domain-modeling 계열 관점으로 검토한다.
- 대화 요약과 작업 인계는 handoff 방식으로 압축한다.
- Hugging Face, 논문, 모델 학습 스킬은 해당 작업이 실제로 필요할 때만 사용한다.
